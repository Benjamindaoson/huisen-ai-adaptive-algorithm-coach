## ADDED Requirements\n\n### Requirement: Capability layers are disclosed separately\nThe system SHALL distinguish local evidence-based learning planning from gateway-backed deep code Mentor analysis and SHALL NOT imply that a model or dynamic tool ran when the gateway is absent or failed.\n\n#### Scenario: Gateway is not configured\n- **WHEN** the Mentor dock has no gateway URL\n- **THEN** it reports local learning planning as available, reports deep code analysis as not connected, and states that no model or dynamic tool was called\n\n#### Scenario: Configured gateway fails\n- **WHEN** the Mentor dock cannot start or recover a configured runtime\n- **THEN** it reports the deep Mentor connection failure while preserving local planning availability and does not show an invented runtime conclusion\n\n### Requirement: Empty-runtime action is route scoped\nThe system SHALL use the current validated route contribution's `nextAction` before a runtime checkpoint exists.\n\n#### Scenario: Current route supplies a next action\n- **WHEN** the current contribution contains a non-empty `nextAction` and no runtime checkpoint exists\n- **THEN** the dock displays that action and not a generic evidence placeholder\n\n#### Scenario: Current route has no next action\n- **WHEN** the current contribution has no valid `nextAction`\n- **THEN** the dock displays a neutral current-task action without claiming a diagnosis\n\n### Requirement: Configured runtime behavior remains intact\nThe system SHALL preserve configured connecting, compiled, agent-analysis, recovery, approval, route isolation, and assessment suppression behavior.\n\n#### Scenario: Runtime successfully recovers evidence\n- **WHEN** the configured runtime returns tool or hypothesis evidence and a checkpoint\n- **THEN** the dock shows the recovered timeline and checkpoint action using the existing evidence references\n\n
