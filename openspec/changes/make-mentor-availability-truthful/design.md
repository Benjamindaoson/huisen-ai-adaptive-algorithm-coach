## Context\n\nThe UI has two real intelligence layers:\n\n1. a deterministic local planner that uses validated learning events to choose lessons and actions;\n2. a gateway-backed Mentor runtime that can compile context, call tools, analyze code evidence, recover runs, and request approvals.\n\nThe persistent dock currently labels an empty `baseUrl` as total Mentor unavailability. That is technically true for layer 2 but visibly contradicts layer 1 on Today and Insights.\n\n## Goals / Non-Goals\n\n**Goals:**\n\n- Make both layers legible in one glance.\n- Keep the no-gateway state useful through a route-derived next action.\n- Keep absence and connection failure honest without implying tool/model execution.\n- Preserve all configured-runtime behavior.\n\n**Non-Goals:**\n\n- Do not implement a local LLM or fake agent trace.\n- Do not change the Mentor API, route contribution schema, or runtime orchestration.\n- Do not redesign the dock or add another Mentor surface.\n\n## Decisions\n\n### 1. Rename the no-gateway state to local planning\n\nThe internal lifecycle uses `local` instead of `unavailable` when no `baseUrl` is configured. Its visible status says local evidence planning is available and deep code analysis is not connected. The empty event explicitly says no model or dynamic tool ran.\n\nThis is preferred over hiding the dock because users need a stable explanation of what the product can and cannot do.\n\n### 2. Treat connection failure as degraded, not total failure\n\nA configured runtime that rejects enters `degraded`. The UI reports the deep Mentor connection failure while keeping the local evidence planner available. It still must not display a runtime event or conclusion that was not recovered.\n\n### 3. Derive the fallback action from the route contribution\n\nBefore a runtime checkpoint exists, the dock reads `contribution.data.nextAction` only when it is a non-empty bounded string; otherwise it uses a neutral current-task action. The route contribution is already workspace-scoped, so this avoids a second planning source and prevents stale cross-route copy.\n\n### 4. Make the shell status name the always-true layer\n\nThe sidebar status becomes `学习编排在线` with a short evidence-based explanation. It no longer vaguely labels the optional deep Mentor as universally available.\n\n## Risks / Trade-offs\n\n- **Users may read “local” as a local model.** Mitigation: explicitly say no model or dynamic tool ran.\n- **Contribution copy may be malformed.** Mitigation: require a trimmed string and cap visible length through the existing validated contribution contract.\n- **Remote failure could hide real runtime evidence.** Mitigation: retain only successfully recovered events; degraded copy never invents results.\n\n
