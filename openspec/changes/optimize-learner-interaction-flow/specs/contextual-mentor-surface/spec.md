## ADDED Requirements\n\n### Requirement: Mentor lifecycle is truthful and learner-legible\nThe persistent Mentor SHALL show a plain-language lifecycle state that distinguishes ready, analyzing, evidence-backed, and unavailable states. It MUST NOT present an online/active claim when no Mentor service or tool evidence is available.\n\n#### Scenario: Mentor service is unavailable\n- **WHEN** no Mentor API base URL is configured or the runtime request fails\n- **THEN** the surface SHALL state that dynamic Mentor analysis is unavailable and SHALL not claim an Agent conclusion.\n\n#### Scenario: Mentor has compiled context but no tool evidence\n- **WHEN** the runtime has synchronized context but has no tool, hypothesis, or verification event\n- **THEN** the surface SHALL state that the Mentor is ready for the current task and SHALL not state that model analysis has occurred.\n\n### Requirement: Mentor prioritizes one next learning action\nThe persistent Mentor SHALL present its next action before operational evidence and SHALL provide evidence references only in a learner-controlled disclosure.\n\n#### Scenario: Runtime has evidence references\n- **WHEN** the Mentor has one or more events with evidence references\n- **THEN** the initial surface SHALL not display raw evidence identifiers and SHALL expose them through a "查看分析依据" disclosure.\n\n### Requirement: Project guidance uses the same Mentor mental model\nThe project workbench SHALL describe its guidance as contextual Mentor guidance and SHALL not imply a separate autonomous project agent.\n\n#### Scenario: Project workbench is active\n- **WHEN** a learner opens a project workbench\n- **THEN** its guidance panel SHALL identify itself as "Mentor guidance" and explain that it offers only the current stage's minimum necessary hint.\n\n
