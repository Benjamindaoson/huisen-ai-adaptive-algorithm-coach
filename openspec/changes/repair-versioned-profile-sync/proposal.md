## Why

The current authenticated browser has 76 durable local writes waiting behind one profile operation. Gateway health and the authoritative profile contract are green, but a profile snapshot generated by a newer frontend can collide with an older queued snapshot that reused the same deterministic operation id. The conflict is thrown before the network request, so manual retry cannot recover.

## What Changes

- Treat profile and versioned state operations as mutable snapshot streams before applying immutable idempotency-conflict rules.
- Replace a queued mutable snapshot with the newest snapshot even when its deterministic operation id is unchanged.
- Keep event and attempt operations strictly immutable: a reused id with different content remains an error.
- Project the raw retry failure into one bounded recovery reason so a learner can distinguish format, session, network, service, and local-queue failures without seeing internals.
- Preserve ordered flushing and recover only through the normal retry path.

## Capabilities

### New Capabilities

- `version-tolerant-learning-sync`: Recover queued mutable learning snapshots after a compatible frontend schema evolution without dropping immutable evidence.

### Modified Capabilities

None.

## Impact

- Changes only local outbox enqueue semantics for profile/state streams.
- Extends the existing safe recovery projection with a bounded reason label.
- Does not delete, skip, reorder, or weaken idempotency for events and attempts.
- Requires a real-browser retry to prove that the existing pending queue can advance.
