## ADDED Requirements\n\n### Requirement: Recap SHALL ask the learner to identify the corrected model\n\nAfter leaving the explanation stage of a verified recovery recap, the system SHALL show the original misconception and corrected explanation as bounded choices.\n\n#### Scenario: Learner selects the original misconception\n\n- **WHEN** the learner selects the original misconception\n- **THEN** the system keeps the recap open\n- **AND** offers a direct return to the human-language explanation\n- **AND** emits no learning event\n\n#### Scenario: Learner selects the corrected model\n\n- **WHEN** the learner selects the corrected explanation\n- **THEN** the “我现在明白了” action becomes available\n- **AND** the interface explains that later independent transfer still verifies mastery\n\n### Requirement: Closure SHALL bind to exact recovery evidence\n\nThe system SHALL persist one bounded metacognitive feedback event for the exact recommendation, return lesson, and source lesson.\n\n#### Scenario: Learner confirms corrected understanding\n\n- **WHEN** the learner confirms the corrected model\n- **THEN** one `lesson-handoff-feedback` signal is emitted with the exact recommendation ID and fixed recap reason\n- **AND** the UI shows that the cognitive correction was recorded\n- **AND** the learner can return to the interrupted lesson\n\n#### Scenario: Existing closure is revisited\n\n- **WHEN** the same verified recovery URL is opened with a matching persisted closure event\n- **THEN** the recorded state is restored\n- **AND** another confirmation cannot emit a duplicate closure\n\n### Requirement: Recap closure SHALL remain mastery-neutral\n\nThe metacognitive feedback SHALL NOT change skill score, confidence, evidence count, lesson completion, or transfer status.\n\n#### Scenario: Mastery is derived with only recap closure\n\n- **WHEN** mastery is derived from no submissions and one valid recap closure event\n- **THEN** skill mastery remains at its no-evidence baseline\n\n
