## Why\n\nThe browser outbox currently truncates itself with `slice(-1000)` while reading and enqueueing. When more than 1,000 writes accumulate offline, the oldest unsent learning evidence disappears without an error, a visible recovery state, or an authoritative server acknowledgement.\n\n## What Changes\n\n- Replace silent truncation with an explicit durable capacity contract.\n- Preserve every already queued operation when capacity is reached.\n- Permit semantic duplicates and mutable-stream replacement without consuming another slot.\n- Let platform synchronization drain a full outbox and continue assembling the same snapshot in bounded batches.\n- Keep failed batches retryable and project existing bounded recovery information to the account UI.\n\n## Capabilities\n\n### New Capabilities\n\n- `durable-outbox-capacity`: Defines lossless capacity, batching, retry, and recovery behavior for browser-to-platform writes.\n\n### Modified Capabilities\n\n- None.\n\n## Impact\n\n- Web outbox persistence and synchronization orchestration.\n- Focused capacity, batching, retry, and recovery tests.\n- No backend API, stored learning-domain schema, dependency, or visible navigation change.\n\n
