## ADDED Requirements\n\n### Requirement: Capacity SHALL NOT evict unsent operations\n\nThe browser outbox SHALL preserve all valid persisted operations until authoritative acceptance or explicitly handled conflict removal. Reaching active capacity SHALL fail before mutation rather than removing an older operation.\n\n#### Scenario: Distinct immutable operation reaches a full outbox\n\n- **WHEN** 1,000 distinct operations are queued and a new immutable operation is enqueued\n- **THEN** enqueue reports the typed capacity condition\n- **AND** the existing 1,000 operations remain byte-for-byte represented in their original order\n\n#### Scenario: Duplicate or replacement does not consume capacity\n\n- **WHEN** the outbox is full and the client enqueues an exact immutable duplicate or replaces an existing mutable stream\n- **THEN** the operation succeeds without increasing queue length or evicting unrelated work\n\n### Requirement: Oversized persisted queues SHALL remain recoverable\n\nThe outbox SHALL read and drain every valid operation from a legacy persisted file even when its count exceeds the current active capacity.\n\n#### Scenario: Legacy file exceeds active capacity\n\n- **WHEN** storage contains 1,001 valid ordered operations\n- **THEN** list returns all 1,001 operations\n- **AND** flush sends them in order without truncation\n\n### Requirement: Platform synchronization SHALL batch at capacity\n\nThe platform synchronizer SHALL treat outbox capacity as a batch boundary rather than a terminal failure.\n\n#### Scenario: Snapshot contains more than one batch of immutable evidence\n\n- **WHEN** an otherwise valid snapshot contains 1,001 unacknowledged events\n- **THEN** synchronization drains the first full batch\n- **AND** sends the remaining event in a following batch\n- **AND** returns synced only after every event is accepted\n\n#### Scenario: Full-batch drain fails\n\n- **WHEN** capacity is reached and the first queued operation cannot be sent\n- **THEN** synchronization returns a bounded pending result\n- **AND** every operation already in the outbox remains retryable\n- **AND** the not-yet-enqueued source record remains reconstructable on the next synchronization attempt\n\n
