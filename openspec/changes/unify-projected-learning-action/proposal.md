## Why\n\nThe same learner state currently produces different next steps in different surfaces. Insights can say `继续 10 分钟训练` while the persistent Mentor says `查看一个最需要补强的技能`. Both are locally derived, but independent copy-generation makes the product feel less intelligent and can send the learner through an unnecessary decision.\n\n## What Changes\n\n- Add one pure action projection for the entry-diagnosis-to-training journey.\n- Represent action state, label, destination, and evidence references together.\n- Make BridgeEntryDiagnosis, Insights, and Mentor route contribution consume the same projection.\n- Preserve existing non-bridge route actions and runtime checkpoints.\n\n## Capabilities\n\n### New Capabilities\n\n- `projected-learning-action`: one evidence-derived next action shared by learner and Mentor surfaces.\n\n### Modified Capabilities\n\n- None.\n\n## Impact\n\n- New pure browser domain module and tests.\n- `BridgeEntryDiagnosis`, `InsightsPage`, and `App` action selection.\n- No backend, model, persistence, event, or route schema changes.\n\n
