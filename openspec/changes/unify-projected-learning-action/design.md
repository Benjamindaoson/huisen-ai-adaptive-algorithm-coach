## Context\n\nThe bridge journey already has a deterministic diagnostic snapshot and bridge plan. However, each UI independently converts those facts into a next action. That duplicates start/resume logic and lets labels drift even when every surface sees the same events.\n\n## Goals / Non-Goals\n\n**Goals:**\n\n- Produce one typed action from validated learning events.\n- Keep label and destination inseparable.\n- Reuse the action in the entry diagnosis, Insights, and Mentor contribution.\n- Cover cold, partial, ready, and resumable states.\n\n**Non-Goals:**\n\n- Do not replace daily-plan, review, project, problem, or exam actions.\n- Do not ask an LLM to choose navigation.\n- Do not change the bridge plan or diagnosis scoring.\n- Do not override a real Mentor runtime checkpoint.\n\n## Decisions\n\n### 1. Add a pure projected action value\n\n`projectBridgeLearningAction(events)` returns an immutable value containing:\n\n- a stable state (`start-diagnosis`, `continue-diagnosis`, `start-training`, `continue-training`);\n- the visible label;\n- a typed application route;\n- the corresponding hash href;\n- exact evidence references already used by the diagnostic projection.\n\nLabel and destination are produced together so they cannot drift.\n\n### 2. Keep bridge action precedence route bounded\n\n`projectMentorNextAction(route, events)` uses the bridge action only on Today and Insights. Existing review and generic route copy remains unchanged. A recovered deep Mentor checkpoint remains higher priority inside `MentorDock`.\n\n### 3. Keep presentation components stateless about action rules\n\nInsights and BridgeEntryDiagnosis may still render different controls, but they use the projected label and route. Components no longer independently inspect training-start events to choose `开始` versus `继续`.\n\n## Risks / Trade-offs\n\n- **Domain module imports application routes.** The action is explicitly a navigation contract, so a typed route is preferable to duplicating string hashes.\n- **Partial diagnosis has no dedicated CTA in the current question UI.** The projection still supplies `继续入口诊断` for Mentor continuity; the current question remains the interaction itself.\n- **A deep Mentor checkpoint can differ from the page CTA.** This is intentional only after a real runtime produced evidence; the shared projection governs the no-runtime fallback.\n\n
