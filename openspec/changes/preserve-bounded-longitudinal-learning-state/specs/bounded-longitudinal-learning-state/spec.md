## ADDED Requirements\n\n### Requirement: Local learning history remains strictly bounded\nThe system SHALL retain no more than 500 learning events in browser memory or file-local gateway learner history, SHALL reserve at most 200 slots for longitudinal milestones, and SHALL retain at least the 300 newest valid events when 500 or more events are available.\n\n#### Scenario: More than five hundred events are retained\n- **WHEN** a valid learner history contains more than 500 events\n- **THEN** the projected local history contains exactly 500 events, includes at least the 300 newest events, and contains no duplicate event IDs\n\n#### Scenario: Small history remains lossless\n- **WHEN** a valid learner history contains 500 or fewer events\n- **THEN** the projected history contains every input event in deterministic chronological order\n\n### Requirement: Longitudinal milestones preserve exact evidence\nThe system SHALL preserve exact validated source events for bounded activation, diagnostic, prerequisite, resume, transfer, mastery-check, and project-completion milestones and SHALL NOT create synthetic completion or mastery events.\n\n#### Scenario: Old activation remains measurable\n- **WHEN** entrance mission, acknowledgement, and first-run events are older than 500 newer activity events\n- **THEN** the projected history retains the original activation event IDs and first-run duration remains derivable from the matching lesson\n\n#### Scenario: Completed prerequisite remains unlocked\n- **WHEN** a lesson-completed event is older than 500 newer activity events\n- **THEN** the projected history retains the original completion event and prerequisite selectors keep the dependent lesson unlocked\n\n#### Scenario: Active training remains resumable\n- **WHEN** an incomplete lesson has a training-session start and completed-stage events older than the recent window\n- **THEN** the projected history retains the latest original start and stage events needed to resume the first unfinished stage\n\n#### Scenario: Transfer and project outcomes remain visible\n- **WHEN** a lesson transfer pass or practicum completion is older than the recent window\n- **THEN** the projected history retains the latest original keyed outcome and its evidence identifiers\n\n### Requirement: Retention is deterministic across storage paths\nThe browser parser/appender and gateway memory/file-local store SHALL apply contract-equivalent milestone keys, priority, ordering, and limits; PostgreSQL SHALL retain complete signed-in event history.\n\n#### Scenario: Browser and gateway receive equivalent history\n- **WHEN** browser and gateway retention receive equivalent validated events in different input orders\n- **THEN** both produce the same ordered set of retained event IDs\n\n#### Scenario: PostgreSQL bootstrap recovers milestones\n- **WHEN** PostgreSQL returns complete history whose milestones are older than 500 recent events\n- **THEN** browser bootstrap projects the full response and retains the recoverable milestones in local memory\n\n### Requirement: Existing memory and backups migrate without invented evidence\nThe system SHALL accept existing learner-memory version 1 and backup versions that contain it, SHALL apply bounded projection to the valid events present, and SHALL NOT claim recovery of evidence absent from the imported payload.\n\n#### Scenario: Existing backup contains recoverable milestone\n- **WHEN** an existing valid backup is imported with a milestone and more than 500 newer events\n- **THEN** import retains the original milestone under the 500-event bound\n\n#### Scenario: Existing backup lacks milestone\n- **WHEN** an existing valid backup does not contain an activation or completion event\n- **THEN** import leaves the corresponding metric or prerequisite unproven rather than synthesizing a fact\n\n### Requirement: Retention cost is measured\nThe project SHALL include a deterministic performance check for projecting 5,000 validated events and SHALL document the measured runtime without weakening correctness checks.\n\n#### Scenario: Performance probe runs\n- **WHEN** the retention performance check projects 5,000 valid events on the supported local runtime\n- **THEN** it reports elapsed time, returns at most 500 events, and preserves the contract milestones\n\n
