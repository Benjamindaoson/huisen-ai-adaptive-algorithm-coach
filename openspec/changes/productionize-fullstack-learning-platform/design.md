## Context

当前 `web` 是 React/Vite 单页应用，`services/runner/gateway` 是 Fastify 模块化网关，代码执行依赖 Judge0，Mentor 可调用 DeepSeek。现状审计证明：前端开发服务器没有注入网关地址；代码运行回退到公共 Judge0；网关以 `file-local`、`permissive-local` 运行；Docker/Judge0 不在线时 `/run` 返回 503；754 道题只有 4 道隐藏判题；考试、练习和部分数字孪生仍以 `localStorage` 为权威；Mentor 真实教师裁决门禁为 0/100。

目标用户主要在中国大陆，同时项目需要成为硅谷招聘者可直接访问和审查的作品集。免费资源可以承载演示，但不具备生产 SLA、备份恢复和隔离执行保障。因此设计采用“一套产品代码、两个部署面、同一套不可降低的接口和质量合同”。

## Goals / Non-Goals

**Goals:**

- 让所有核心用户流程以服务端数据和真实接口为权威，并在浏览器断网后安全恢复同步。
- 让 754 道题全部拥有版本化、服务器专用、可审计的隐藏判题包。
- 让 Mentor 的每个结论绑定提交、工具、执行和代码差异证据，并通过真实教师评测门禁。
- 建立可在国内云生产运行、也可供全球招聘者体验的可复现部署。
- 用自动化证据定义“100% 完成”：合同、测试、覆盖、SLO、安全、恢复和人工验收全部通过，而不是宣称零缺陷。
- 免费用户可以完成基础学习闭环，同时用硬配额保护代码执行和 AI 成本。

**Non-Goals:**

- 第一阶段不建设招聘市场、直播课堂、教师 SaaS 或企业 ATS。
- 第一阶段不采用 Kubernetes、多区域主动—主动数据库或自研大模型。
- 不把自动生成但未经执行和审核的测试计入 754 题覆盖。
- 不把免费演示环境包装成生产环境，不承诺永久零云成本。
- 不用模型输出直接修改权威掌握度、判题结果或教育评价。

## Decisions

### 1. 采用模块化单体网关与隔离判题池

Fastify 网关保持单一可部署进程，但按 `identity`、`learning`、`assessment`、`mentor`、`entitlements`、`operations` 六个深模块组织；调用者只使用版本化 HTTP 合同。Judge0 是独立安全域，运行在专用 VM/节点池和私有网络，不能与网关、数据库或模型密钥同宿主机。

选择它而不是立即拆微服务，是因为当前规模不需要分布式事务和额外运维；代码执行的特权边界却必须物理拆开。未来只有当独立扩缩或故障域数据证明必要时才拆网关模块。

### 2. PostgreSQL 是业务事实源，Redis 只承担短期协调

PostgreSQL 保存用户、会话、学习事件、练习尝试、不可变提交快照、考试、导师运行、工具证据、配额账本、内容版本和审计事件。Redis 用于限流、幂等窗口、短期任务协调和 Judge0 自身队列；任何不可重建的业务事实不得只存在 Redis。对象存储保存较大的执行工件、导出和备份。

浏览器 IndexedDB/localStorage 只作为缓存、草稿和离线 outbox。服务端返回单调版本和幂等回执，冲突按字段所有权处理：代码草稿最后写入可合并，学习事件只追加，考试和判题结果只能由服务端写入。

### 3. 自托管身份核心，接口允许未来接 OIDC

首版正式身份使用 Argon2id 密码哈希、短期访问会话、旋转刷新会话、HttpOnly/Secure/SameSite Cookie、CSRF 防护、邮箱验证、找回流程、设备与会话撤销。匿名体验生成受限身份，注册后执行一次幂等数据归属迁移。角色至少包含 learner、reviewer、admin；所有资源查询强制包含 owner/tenant 条件。

选择自托管核心是为了中国可达性和成本可控；身份模块外部接口保持 OIDC-compatible seam，未来可接企业 SSO。生产环境没有身份密钥或仍处于 permissive 模式时启动失败。

### 4. 判题以不可变内容版本和异步提交为核心

前端只提交 `problemVersionId`、语言和源码；网关写入不可变快照并返回 submission ID。后台调用私网 Judge0，持久化状态机和聚合结果。隐藏输入、期望输出、参考答案和测试生成种子永不进入浏览器包或公共日志。

每道题必须满足发布清单：规范化题面哈希、至少一个人工认可参考实现、至少 10 个隐藏测试、边界/异常/性能类别覆盖、两种独立 oracle 或人工复核、四语言编译冒烟、篡改检测和版本回滚。自动生成测试只有在差分执行、去重、可信等级和人工抽检通过后才能晋级。

### 5. Mentor 是证据驱动 Runtime，不是聊天转发

Mentor 运行状态机固定为 Observe → Hypothesize → Acquire evidence → Intervene → Verify revision → Transfer check → Stop/Replan。模型只能选择白名单工具；工具参数先做 schema 和策略校验。执行器提供提交快照、AST/CFG、公开/隐藏安全摘要、差分测试、可信 RAG、学习阶段和历史提示依赖。

模型不可读取隐藏用例正文，不可直接改学生代码或掌握度，不可在独立考试中运行。每次调用记录 trace、模型版本、token、延迟、工具、证据引用、策略决定和降级原因。DeepSeek 不可用、超预算或置信度不足时进入确定性最小提示或停止，不伪造诊断。

### 6. 前端不得静默降级为另一套产品

所有远端能力通过一个 `PlatformClient` 接口和生成/校验后的 `/api/v1` 合同访问。生产构建必须配置 API origin；健康探测展示数据库、判题、模型和质量门禁的分项能力。代码执行不再回退公共 Judge0，Mentor 不再回退伪 AI，服务不可用时显示可恢复错误和排队状态。

离线允许浏览已缓存内容、编辑草稿和生成待同步学习事件；不允许离线伪造通过、考试分数、AI 工具轨迹或云端配额。

### 7. 中国生产面和全球作品集面共享发布物

国内生产优先使用阿里云、腾讯云或华为云中国大陆节点：静态对象存储/CDN、两台网关最小高可用、托管 PostgreSQL、同地域 Redis、对象存储、专用 Judge0 VM 池。正式开通域名前执行 ICP/公安备案检查；收费前单独核验经营许可要求。

全球作品集面使用同一容器镜像和前端构建，可放在 Cloudflare Pages 与低成本海外 VM/数据库，只加载脱敏演示租户、严格低配额和有限判题集。全球 Demo 的失败不得影响中国生产数据，两个环境不共享数据库或密钥。

基础设施使用 OpenTofu/Terraform 模块、Docker 镜像、GitHub Actions 和环境清单复现。首个生产 adapter 选一个国内云实施，其他供应商保持文档级可替换，不同时维护三套云脚本。

### 8. Freemium 由服务端权益账本强制执行

免费层开放全部题面、基础课程、学习进度、有限每日运行、有限 Mentor 回合和每周模拟考试。Pro 增加运行/AI 配额、云同步历史、深度诊断、迁移题、报告和模拟面试。服务端以不可变使用账本和原子扣减决定是否执行，前端计数仅作展示。

第一阶段先实现 entitlement、quota 和成本账本，不在未确定支付主体和许可前绑定真实支付渠道。Admin 可发放测试权益，但必须有审计记录和过期时间。

### 9. 发布以证据包和 SLO 门禁为准

生产目标：核心读取 API 月可用性 99.9%，判题接受 API 99.9%，95% 小程序运行在 10 秒内完成，Mentor 首个可见事件 P95 小于 3 秒；RPO 15 分钟、RTO 60 分钟。CI 必须运行单元、契约、集成、端到端、安全和迁移测试；预发布必须完成容量、故障、恢复和回滚演练。

发布证据包至少包含：754/754 判题清单、100+ 真实教师裁决 Mentor 报告、0 个 Critical/High 未接受安全问题、负载报告、备份恢复报告、数据迁移对账、浏览器关键路径录像/截图、成本上限和变更回滚记录。任何硬门禁不通过，流水线拒绝生产发布。

## Risks / Trade-offs

- [754 道题内容质量远大于编码工作量] → 建立分批内容工厂和可信等级；未达标题目可学习但不得标注“完整判题”。
- [Judge0 特权容器存在逃逸和资源滥用风险] → 独立 VM 池、私网、无云凭证、出站默认拒绝、临时文件系统、资源上限、镜像扫描和定期重建。
- [自托管身份增加安全责任] → 使用成熟密码库和 cookie 会话模式，渗透测试、密钥轮换与强制生产启动检查；后续可通过同一 seam 换成 OIDC。
- [双部署面增加运维面] → 共享容器和合同，只隔离配置、数据和 IaC adapter；全球面保持受限只读/低配额。
- [免费用户造成不可控 AI/执行成本] → 服务端原子配额、队列优先级、token/时间上限、缓存、预算熔断和确定性降级。
- [模型诊断可能错误或泄题] → 真实教师金标、泄题检测、证据充分性门禁、独立考试硬禁用、人工纠错和版本回退。
- [浏览器本地数据迁移产生重复或冲突] → 幂等事件 ID、导入预览、对账报告、可逆迁移和一段时间双读验证。
- [“100%”被误解为永不故障] → 只使用可验证验收定义；上线后持续用 SLO、错误预算和事故复盘衡量。

## Migration Plan

1. 建立本地完整栈、版本化合同、数据库 schema、测试数据和 CI 基线；保持旧前端可用。
2. 上线身份与服务端学习数据，导入现有浏览器数据；灰度双写并生成逐用户对账报告。
3. 接通统一 PlatformClient，逐个关闭公共 Judge0、本地权威状态和 permissive 生产回退。
4. 将提交持久化并接入隔离 Judge0；先发布 50 道金标题，再分批扩至 754/754。
5. 接通 Mentor Runtime、追踪和质量工作台；在 100 条真实教师裁决门禁通过前保持实验标签。
6. 完成配额、可观测、安全、备份恢复和负载演练，发布全球 Demo。
7. 完成国内云 IaC、备案前置条件和预发布演练，灰度 1%、10%、50%、100% 国内生产流量。
8. 每阶段保留数据库迁移 down/forward 修复方案、前端前一版本和容器前一镜像；数据迁移只追加或先扩后缩，回滚不得丢失新事件。

## Open Questions

- 国内首个生产云供应商在执行前根据账号可用额度选择阿里云、腾讯云或华为云；计划默认 IaC provider seam，不影响业务模块实施。
- 真实收费渠道和经营许可在 entitlement 完成后单独立项；本次不以接入支付作为核心后端上线的阻塞项。
- 100 条教师裁决需要真实教师或经授权评审者，代码可以完成采集、盲评和门禁，但不能自动伪造这项外部证据。
