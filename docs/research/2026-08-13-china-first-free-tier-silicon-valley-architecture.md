# 中国优先、免费层与硅谷作品集架构研究\n\n> 日期：2026-08-13\n> 研究范围：中国大陆访问与部署、免费/低成本全栈架构、Judge0 与 DeepSeek、硅谷 AI-native 产品基线、求职作品集评价标准。\n> 证据规则：仅引用官方文档、官方产品页、官方代码仓库、官方标准或主管部门文件。价格和免费层会变化，上线前必须重新核价。本文不是法律意见。\n\n## 一、结论先行\n\n1. **人在中国、主要服务中国大陆用户时，不建议把 Vercel 或 Cloudflare 全球免费网络当生产主站。** Vercel 官方明确说明其在中国大陆没有服务器或 CDN 节点，可能出现性能下降或无法访问，并且不能保证大陆可用性；Cloudflare 真正的中国大陆网络只对 Enterprise 客户开放，还是单独订阅，并要求 ICP 备案。[Vercel：中国大陆访问说明](https://vercel.com/kb/guide/accessing-vercel-hosted-sites-from-mainland-china)；[Cloudflare China Network](https://developers.cloudflare.com/china-network/)\n2. **中国大陆生产主站应优先选择阿里云、腾讯云或华为云的大陆节点，完成 ICP 备案；AWS 中国区更适合已有中国大陆企业主体的团队。** AWS 官方当前说明中国区账户只向中国大陆法人实体开放，而且中国区账户、凭证、运营主体和全球区相互独立。[AWS 中国区注册 FAQ](https://www.amazonaws.cn/en/about-aws/china/faqs/signup/)；[AWS 中国区账户与凭证](https://docs.amazonaws.cn/en_us/aws/latest/userguide/accounts-and-credentials.html)\n3. **“零元生产上线”在本项目上不成立。** React 静态站、个人作品集网关、PostgreSQL 和 Redis 可以用免费层做演示；但 Judge0 官方部署需要 `privileged: true`，必须为不可信代码准备隔离计算资源；DeepSeek API 按 token 扣费；中国大陆公开服务还需要满足可备案资源条件。这三项共同决定了真实生产必然有持续成本。[Judge0 官方 Compose](https://raw.githubusercontent.com/judge0/judge0/master/docker-compose.yml)；[DeepSeek 模型与价格](https://api-docs.deepseek.com/quick_start/pricing/)\n4. **技术选型放在硅谷并不落后，但“React + Fastify + PostgreSQL + Redis + LLM”本身也不先进。** 真正先进且有求职信号的是：隔离执行、可重放的 Agent trace、确定性工具、评测门禁、学习结果验证、SLO/可观测性、安全控制、自动化交付和恢复演练。\n5. **推荐采用“一套代码、两个部署面”：** 中国大陆生产面使用国内云和备案域名；全球作品集预览面使用 Cloudflare Pages 或 Vercel、Neon、Upstash 等免费层。两边共享 API 合同、容器镜像、迁移、测试和基础设施定义，避免维护两个产品。\n\n---\n\n## 二、证据口径\n\n- **官方事实**：来源直接属于服务提供商、开源项目所有者、标准组织或中国主管部门。\n- **本文推断**：基于官方事实给出的架构或产品判断，官方没有替本项目背书。\n- **不能断言**：供应商未公开的数据，例如中国各省跨境网络的实际 P95、免费层 SLA、竞品内部数据库与 静态文件（对象存储/CDN，或 Nginx）\n        |\nFastify API（容器，至少健康检查、滚动部署、限流）\n        |\nPostgreSQL（托管优先） + Redis（托管优先）\n        |\n提交队列 / 不可变 Submission Snapshot\n        |\n独立 Judge0 私网节点（无业务密钥、默认禁外网、资源配额）\n        |\nDeepSeek API（仅服务端调用、预算与降级）\n```\n\n**本文推断：最低成本但诚实的分层方式如下。**\n\n- 公开测试期：一台小型大陆云主机运行 Fastify、PostgreSQL、Redis；第二台独立主机只运行 Judge0；数据库定时加密备份到对象存储，并做恢复演练。这不是高可用生产，只是避免了最危险的“判题与业务数据同宿主”。\n- 正式付费期：Fastify 至少两副本 + 负载均衡；托管 PostgreSQL 开启自动备份/PITR；托管 Redis 或可重建缓存；至少两个可横向扩展的 Judge worker；发布可回滚；关键路径有 SLO、告警和容量测试。\n- 1,000–10,000 用户不能仅凭注册人数估容量。必须用活跃并发、每用户提交次数、语言冷启动、执行时间、峰值队列长度、AI token/会话和存储增长做压测。任何固定月费数字在这些输入缺失时都只是猜测。\n\n### 4.3 Judge0 的隔离是硬门禁\n\n**官方事实：** Judge0 官方 Compose 为 server 和 worker 设置 `privileged: true`；Docker 官方说明 privileged 容器获得全部 Linux capabilities、访问宿主全部设备，并被调整到几乎与宿主进程相同的访问级别，要求谨慎使用。[Judge0 Compose](https://raw.githubusercontent.com/judge0/judge0/master/docker-compose.yml)；[Docker privileged 说明](https://docs.docker.com/engine/containers/run/#runtime-privilege-and-linux-capabilities)\n\n**本文推断：**\n\n- Judge0 不得与 Fastify、生产 PostgreSQL、Redis、CI runner 或云密钥同宿主机。\n- Judge 网段默认拒绝访问数据库、云元数据地址、内网控制面和公网；只允许从受控队列取任务、向结果通道写结果。\n- 运行身份不持有 DeepSeek、数据库、对象存储管理密钥；每次运行设置 CPU、内存、进程、文件、时间和输出上限。\n- 保存镜像 digest、语言版本、提交快照、测试版本、执行限制和结果，以便重放。\n- 对沙箱逃逸、fork bomb、超大输出、网络扫描、恶意包和并发耗尽做专门红队测试。\n\n这项隔离没完成，无论 UI 和 AI 多完整，都不能声称生产就绪。\n\n### 4.4 DeepSeek 的成本与可靠性控制\n\n**官方事实：** DeepSeek 当前按 1M token 对缓存命中输入、未命中输入和输出分别定价；费用从充值或赠送余额扣除，供应商保留调价权；余额不足、限速和服务过载分别可能出现 402、429 和 503。[DeepSeek Pricing](https://api-docs.deepseek.com/quick_start/pricing/)；[Error Codes](https://api-docs.deepseek.com/quick_start/error_codes/)；[Rate Limit & Isolation](https://api-docs.deepseek.com/quick_start/rate_limit)\n\n**本文推断：** 生产网关至少需要：API key 只在服务端、按用户/课程预算、最大 token、超时、指数退避、幂等、熔断、模型降级、缓存、prompt/version 记录、token/延迟/错误 trace，以及 AI 不可用时仍能提交和判题的确定性降级路径。\n\n---\n\n## 五、哪些“免费”不是真正的免费生产\n\n| 服务 | 为什么不能当永久免费生产承诺 |\n|---|---|\n| Vercel Hobby | 官方只允许个人、非商业用途；超限时功能或部署可能暂停；没有大陆基础设施保证。 |\n| Cloudflare Free | 全球 Pages/Workers Free 与 API 合同、数据库迁移、队列幂等、备份恢复、灰度/回滚、SLO 和安全扫描有自动化证据。\n\nAnthropic 官方尤其强调，成功不是复杂度最高，而是用评测证明“正确复杂度”；所以堆 Kubernetes、向量库或多个 Agent 并不会自动增加硅谷含金量。[Anthropic: Building Effective 中国开发环境：领取阿里/腾讯/华为官方试用做兼容、压测和备案流程预演，不把试用资格写进长期架构。\n- 代码层：保持 React、Fastify、PostgreSQL、Redis 和 Judge0 的供应商中立接口，所有环境共用迁移、OpenAPI、Docker 镜像和测试。\n\n### 真正对中国用户上线\n\n- 在阿里云、腾讯云、华为云中选择一个大陆供应商，购买满足备案条件的长期资源并完成 ICP/公安备案；以个人还是单位主体，应由网站实际内容和经营模式决定。\n- 先使用容器和托管数据服务，不为“看起来先进”提前上 Kubernetes；当多节点调度、弹性和团队运维成本由数据证明后再引入。\n- Judge0 使用独立节点/安全边界；这是首要付费项，不应省略。\n- 对公众提供 AI 辅导前完成生成式 AI、内容标识、未成年人和个人信息合规核对。\n\n### 面向硅谷求职\n\n- 保留一个海外 recruiter 可稳定访问的免费预览；中国主站与全球预览应展示相同 Git SHA 和 API 合同。\n- README 使用中英双语，明确成本、合规、故障域和 trade-off。\n- 把项目叙事从“我用了很多先进技术”改成：**“我构建了一个可以隔离执行不可信代码、用证据驱动 AI 辅导，并用独立迁移题验证学习效果的系统。”**\n\n最终判断：**这套方向有机会成为硅谷求职中的强项目，但前提是上述能力有运行证据。免费层足以做展示，不足以支撑中国大陆、含不可信代码执行的完整生产服务。**\n
