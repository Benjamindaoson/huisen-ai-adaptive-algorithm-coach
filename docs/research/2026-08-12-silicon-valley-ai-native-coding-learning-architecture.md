# 硅谷 AI 原生编程学习产品与 Agent 架构对标\n\n> 日期：2026-08-12\n> 范围：CodeSignal Learn/Cosmo、Codecademy AI Learning Assistant/AI Builder、Khanmigo、Coursera Coach，以及 Anthropic、GitHub Copilot、Replit Agent 对 Mentor OS 的架构启示。\n> 证据规则：仅采用产品方官方文档、官方博客或产品方作者论文。每节严格区分“官方公开事实”和“合理架构推断”。产品方没有公开的内部实现，不因营销用语而补全。\n\n## 一、结论摘要\n\n目前没有一家公开证明同时具备以下全部能力：\n\n1. 编程学习、独立测评与长期能力档案闭环；\n2. 基于 AST、执行、测试和提交快照的证据级代码诊断；\n3. 会根据证据不足自主选工具、重规划、验证和停止的 Mentor Agent；\n4. 将提示依赖、误区、迁移和遗忘纳入可解释学习者模型；\n5. 以“下一道不同表面题能否独立完成”作为核心发布指标。\n\n四个教育产品中：\n\n- **CodeSignal** 的优势是“学习—受保护测评—技能验证”的完整产品闭环；\n- **Codecademy** 的优势是课程/代码上下文、RAG、项目即课程及 5E 苏格拉底式体验；\n- **Khanmigo** 公开了最成熟的学习效果实验、上下文工程、专项验证 Agent 和回归门禁；\n- **Coursera** 强在可信课程内容 grounding、课程内常驻交互，以及辅导与高风险测评隔离。\n\n通用 Agent 产品进一步说明：成熟 Agent 的技术代差不来自多个角色名称，而来自动态工具循环、最小高信号上下文、隔离执行、可恢复状态、完整日志、人工批准和可持续评测。\n\n因此，本项目应建设一个**单一 Mentor OS + 确定性专业工具 + 证据与策略层**，而不是继续堆叠多个聊天角色。\n\n---\n\n## 二、CodeSignal Learn / Cosmo\n\n### 2.1 官方公开事实\n\n- Cosmo 内置于 最可能采用确定性课程/测评平台作为底座，在 IDE 与课程上下文上叠加 LLM Tutor。公开资料不足以证明它是通用 Agent Runtime。\n\n对本项目最重要的启示不是复制聊天框，而是复制这条闭环：\n\n```text\n基线/目标 → 个性化路径 → IDE 实践 → Tutor 支持\n         → 受保护的独立 Assessment → 可验证技能档案\n```\n\n---\n\n## 三、Codecademy AI Learning Assistant / AI Builder\n\n### 3.1 官方公开事实\n\n- Assistant 的上下文包含学习者所处练习和 checkpoint、课程/solution code、学习者已写代码及练习进度；支持选中代码后直接解释，并可连续追问。[Behind the Build: 进一步测试了向上下文加入近期练习尝试、对错、技能水平和先修掌握情况。[How Khan Academy Is Building a Better AI Tutor](https://blog.khanacademy.org/how-khan-academy-is-building-a-better-ai-tutor-our-most-recent-learnings/)\n- Khanmigo 后台存在专项 `math agent`，实时验证计算和数学表达式。官方还测试了更快模型、精简专项 Agent 输出、缩紧超时，以及调用前 pre-check，以减少不必要的数学验证调用。[同一官方复盘](https://blog.khanacademy.org/how-khan-academy-is-building-a-better-ai-tutor-our-most-recent-learnings/)\n- 向 Tutor 提供近期问题尝试摘要后，下一道同技能题的独立正确率提高 3.4%；发现未掌握先修并提供简短复习后提高 2.7%。[同一官方复盘](https://blog.khanacademy.org/how-khan-academy-is-building-a-better-ai-tutor-our-most-recent-learnings/)\n- 直接传入当前会话 JSON 没有显著效果；改为纯文本，并加入过去 24 小时内同技能线程后，认知参与指标提升 5.09%。Khan Academy 表示下一步将提取日志中“教学上有意义”的部分，而非继续传入原始日志。[同一官方复盘](https://blog.khanacademy.org/how-khan-academy-is-building-a-better-ai-tutor-our-most-recent-learnings/)\n\n### 4.2 官方公开事实：评测与发布门禁\n\n- Khan Academy 将响应延迟、辅导后下一道同技能题且不使用 Khanmigo 的正确率，以及 ICAP 式认知参与作为三项核心指标；同时监控提前泄露答案、数学错误率和每线程交互数等 guardrail。[官方复盘](https://blog.khanacademy.org/how-khan-academy-is-building-a-better-ai-tutor-our-most-recent-learnings/)\n- A/B 测试只有在预测胜率超过 0.95，且 guardrail 没有负向变化时才发布。官方称六个月约 20 项测试覆盖超过 1,500 万 tutoring threads。[官方复盘](https://blog.khanacademy.org/how-khan-academy-is-building-a-better-ai-tutor-our-most-recent-learnings/)\n- Khan Academy 作者的论文先以专家 rubric 标注约 106/107 条对话，再用 GPT-4o Batch API 建立 LLM Judge。论文报告 human–LLM agreement 约 87%–94%，Krippendorff's alpha 约 0.688–0.796；系统还使用答案泄露 Judge、确定性语言复杂度/可读性/情感标签器及 embedding 重复度标签器。[Cognitive Engagement in GenAI Tutor Conversations](https://aclanthology.org/2025.aimecon-wip.6.pdf)\n- 论文明确其学习结果是观察性、同技能近迁移关联；未来 Tutor 使用和未观测变量仍可能混杂结果，不能当作远迁移因果证明。[同一论文](https://aclanthology.org/2025.aimecon-wip.6.pdf)\n\n### 4.3 4.4 合理架构推断\n\n公开材料支持将 Khanmigo 描述为：\n\n```text\n主 Tutor\n  + 结构化 mastery / prerequisite / recent-attempt context\n  + 专项数学验证 Agent\n  + 确定性与模型化质量标签器\n  + A/B 实验和 guardrail 发布门禁\n```\n\n它不是已公开证明的通用 官方公开事实\n\n- Anthropic 明确区分 workflow 和 agent：workflow 的路径由代码预定义；agent 由 LLM 动态决定过程和工具使用。其建议从最简单方案开始，仅在评测证明收益时增加复杂度。[Building Effective Agents](https://www.anthropic.com/engineering/building-effective-agents)\n- 基础单元是 augmented LLM，即模型加 retrieval、tools 和 memory。官方列举 prompt chaining、routing、parallelization、orchestrator-workers 和 evaluator-optimizer 等模式，并强调可组合、透明和经过测试的 Agent-Computer Interface。[Building Effective Agents](https://www.anthropic.com/engineering/building-effective-agents)\n- Context engineering 的目标是在有限 attention budget 中保留最小、高信号信息。Anthropic 建议混合“预先加载稳定指令”和“运行时 just-in-time 工具检索”，并使用 progressive disclosure、compaction 和结构化笔记处理长任务。[Effective Context Engineering for AI Agents](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)\n- Anthropic 对 Agent eval 的定义覆盖完整多轮 transcript、工具调用、环境状态改变和最终结果；建议同时评估任务是否完成、过程是否破坏状态及输出质量，而不是只评估最后一段文字。[Demystifying Evals for AI Agents](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)\n\n### 对 Mentor OS 的合理应用推断\n\n- 教学阶段、考试规则和能力更新适合确定性 workflow；错误诊断中的证据获取适合受限 Agent loop。\n- Context Assembler 不应把所有历史塞入 Prompt，而应预载当前目标和策略，再允许 Agent 按需读取提交、运行结果、技能图和历史关键事件。\n- 每一次 Mentor Run 都应保存完整工具轨迹、状态变化和停止原因；质量评测同时检查诊断结果、干预过程、泄题和迁移结果。\n- 不因框架存在而宣称 Agent。只有模型真实决定下一项工具，并能根据结果重规划和停止时，才满足动态 Agent 定义。\n\n## 6.2 GitHub Copilot cloud agent：隔离执行、可审查交付与最小权限\n\n### 官方公开事实\n\n- Copilot cloud agent 可以研究仓库、制定计划、在分支修改代码并创建 Pull Request；工作运行在 GitHub Actions 驱动环境中，开发者通过 diff、commit、session log 和 PR 审查结果。[About Copilot Cloud Context Assembler\n│  ├─ 当前题目 / 课程 / checkpoint\n│  ├─ immutable submission snapshot + current diff\n│  ├─ compile / run / tests / AST evidence\n│  ├─ verified learner phase / skills / prerequisites\n│  └─ intervention history + answer-reveal budget\n├─ Planner State Machine\n│  Observe → Hypothesize → Acquire evidence → Intervene\n│          → Observe revision → Transfer test → Stop / Replan\n├─ Deterministic Tools\n│  ├─ isolated sandbox runner\n│  ├─ AST / CFG / data-flow analyzer\n│  ├─ test / counterexample / differential testing\n│  ├─ trusted RAG with provenance\n│  ├─ curriculum / prerequisite selector\n│  └─ event-driven learner-state projector\n├─ Policy Layer\n│  ├─ practice / no-AI exam / AI-collaboration mode\n│  ├─ answer-vault and network isolation\n│  ├─ hint escalation / leakage / confidence rules\n│  └─ student and teacher approval boundaries\n└─ Event, Trace and Evaluation Stores\n   ├─ append-only learning events\n   ├─ agent runs / tool calls / latency / cost\n   ├─ content provenance and trust level\n   ├─ teacher gold labels and disagreements\n   └─ transfer and delayed-review outcomes\n```\n\n### 8.1 哪些必须由代码控制\n\n- 考试模式权限、答案隔离、可调用工具和网络范围；\n- 提交快照、运行结果、diff、事件写入和能力分更新；\n- 课程先修图、提示等级、复测时间和证据可信等级；\n- 高风险结论的置信阈值、人工升级与发布门禁。\n\n### 8.2 哪些可以由 Mentor 动态决定\n\n- 当前诊断最缺少哪项证据；\n- 调用静态分析、测试生成、运行或 RAG 的顺序和参数；\n- 根据新证据保留、修正或放弃假设；\n- 在策略允许范围内选择最小教学干预；\n- 证据足够或学生已掌握时停止本次 Agent Run。\n\n### 8.3 用户可感知的 AI 原生界面\n\nAI 不能只存在于一个聊天 Tab。编辑器旁的 Mentor 时间线应持续显示：\n\n1. 我正在分析哪一次提交；\n2. 我观察到的事实；\n3. 当前假设和置信状态；\n4. 还缺少什么证据；\n5. 刚调用的工具、输入范围和结果；\n6. 建议学生只修改哪里、为什么不直接给答案；\n7. 修改后假设是否被验证；\n8. 为什么安排这道迁移题或延迟复测；\n9. 本次 Mentor Run 为什么停止。\n\n---\n\n## 九、无法伪装的验收标准\n\n第一阶段不能以“Agent 可以聊天”验收，应满足：\n\n1. 每个 Mentor 结论绑定提交快照、运行结果、工具调用和当前 diff；\n2. 模型能够真实选择工具，并至少一次根据工具结果修改计划；\n3. 证据不足时明确停止下结论或升级人工，不得补全想象；\n4. 学生代码、答案提交和能力评分不由 Agent 直接修改；\n5. 每个诊断可在内部工作台完整重放；\n6. 发布门禁至少覆盖错误定位、错因、证据充分、最小提示、直接泄题、错误结论、延迟和成本；\n7. 核心产品指标是辅导后隐藏迁移题和延迟复测的独立表现；\n8. 无 AI 考试在权限层真正切断 Tutor、答案库与外部模型；\n9. Agent Run 有明确最大步骤、预算、超时、停止原因和可恢复 checkpoint；\n10. 任何“超越竞品”的表述必须来自教师金标、真实 A/B 或纵向学习实验，而不是模型自评。\n\n## 十、最终战略判断\n\n如果本项目只是“700 道题 + 在线运行 + DeepSeek 聊天”，CodeSignal 的完整闭环、Codecademy 的上下文体验和 Coursera 的内容规模都会构成不可逾越的差距。\n\n真正可形成代差的路线是：\n\n> 把 Khanmigo 的学习效果门禁、CodeSignal 的独立技能验证、Codecademy 的项目即课程、Coursera 的可信内容与高风险测评隔离，再叠加 GitHub/Replit 式隔离执行、日志、checkpoint 和人工批准。\n\n最终价值主张不是“AI 帮你做出这道题”，而是一个可以被证据验证的承诺：\n\n> **Mentor 只提供最小必要帮助，并证明学习者能够独立做出下一道不同表面的题。**\n
