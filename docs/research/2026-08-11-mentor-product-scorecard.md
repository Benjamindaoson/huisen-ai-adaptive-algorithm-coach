# Mentor AI 产品完成度评分卡

> 评估日期：2026-08-11。评分对象是当前可运行产品，不是愿景文档。证据来自自动化测试、真实 Judge0、真实 DeepSeek、PostgreSQL 重启和浏览器主流程；未经过用户实验的部分不按“已证明有效”计分。

## 结论

当前版本综合评分 **8.1 / 10**。它已经从“题库 + 编辑器 + 假 Agent 标签”升级成一个有真实模型决策、工具调用、代码证据、学习状态、持久化和安全边界的 AI 编程学习工作台。

产品层面已经达到值得继续投入的工程原型标准，但还没有达到可以仅凭产品数据做规模化投资决策的阶段。下一道门槛不是再堆 Agent 名称，而是证明三件事：诊断准确率、学习效果提升、连续使用留存。

## 已经真正实现的能力

1. **真实 Agent，而不是角色卡片。** DeepSeek 通过原生 tool calls 选择语法检查、证据检索、反例生成、假设验证、学习者提问、数字孪生更新和主动结束；工具结果会进入下一次模型决策。
2. **模型能够犯错并纠错。** 非法工具名、参数结构和重复调用不会直接穿透执行层。拒绝原因会作为工具结果回传；模型有机会修正，连续三次失败才安全降级。
3. **代码诊断有可追溯证据。** 静态结构、语义图、运行时状态、实际输出和期望输出使用不同证据引用；静态猜测不会被冒充成已验证结论。
4. **教学闭环进入主界面。** 导师先要求学生预测状态，根据回答缩小到最小修改，再观察重新提交，并用不同题验证迁移；AI 不再藏在孤立 Tab 中。
5. **状态不是浏览器假数据。** Mentor 会话和学习者数字孪生由 PostgreSQL 保存；签名身份限制所有者访问；浏览器仍可保留第一版草稿/备份能力。

## 本轮验证证据

- `npm run verify`：76 个测试文件、284 个测试通过；lint、语料质量门禁、双端类型检查和生产构建通过。
- 真实 Judge0：JavaScript、Python、Java、C++ 均成功捕获 `i=1, sum=2` 的结构化运行时状态。
- 参考解共识：同一输入由 Python 与 JavaScript 独立执行并一致得到 `5`，权威等级为 `reference-consensus`；Java/C++ 本次未计入成功集合，因此没有虚报四语言共识。
- 持久化与身份：DeepSeek 模式创建 Mentor 会话，Gateway 重启后 session/timeline 保持；跨用户读取返回 404，不泄漏会话存在性。
- 浏览器：题目、编辑器和 Mentor 同时存在；10 条时间线事件；提交预测后进入 `awaiting-edit`；显示“PostgreSQL 持久化 · 签名身份”；控制台 0 错误。
- 依赖与配置：根项目、Web、Gateway 三次 `npm audit --audit-level=high` 均为 0 漏洞；严格 OpenSpec 和 Compose 配置校验通过；未检出硬编码 API token 特征。

## 仍然存在的产品上限

这些不是本轮承诺漏做，而是从 8.1 分迈向 9 分必须解决的下一阶段问题：

1. 建立至少 300–500 道题的人工金标用例和典型错误集，测量诊断 precision/recall，而不是只看演示是否合理。
2. 用真实学习者做对照实验，验证首题通过率、提示依赖下降、迁移题通过率和 7/30 日留存。
3. 给“导师正在分析的提交快照”增加可视化 diff/版本定位，避免用户把旧提交诊断误认为当前代码诊断。
4. 将结构分析升级为按语言逐步增强的类型与数据流后端；优先 Java/Python，而不是一次追求四语言编译器完备性。
5. 增加可恢复账户、设备迁移、组织权限、审计日志、密钥轮换和生产级执行资源隔离。

## 投资判断

如果只看当前产品，我会给出“**继续投入、以验证指标为前提**”的判断，而不是直接做规模化下注。技术真实性已经跨过门槛：Agent、判题、证据、学习状态和持久化都不是演示壳。下一轮投资是否加码，应由三项硬指标决定：诊断准确率达到可接受基线、迁移题表现显著优于无 Mentor 组、四周留存证明用户愿意持续使用。
