# Evidence Learning Platform v1 Implementation Plan\n\n> **For agentic workers:** Use test-driven development. Independent modules may be implemented in parallel, but shared integration files are owned by the primary worker.\n\n**Goal:** Deliver the first trustworthy product phase spanning mentor quality governance, semantic learning telemetry, beginner adaptive instruction, dual-mode algorithm screening, and trusted content generation.\n\n**Architecture:** Extend the current React/Fastify/local-first application with pure TypeScript domain modules, JSON quality artifacts, bounded gateway persistence, and internal routes. Preserve compatibility with existing learner events and exam sessions. Treat OpenSpec change `build-evidence-learning-platform-v1` as the acceptance contract.\n\n**Tech Stack:** React 19, TypeScript 6, Vite 8, Vitest 4, Node.js ESM, Fastify 5, PostgreSQL-compatible gateway store, existing Tree-sitter and Judge0 integrations.\n\n**Global Constraints:** Never count synthetic cases as real evidence. Never let model output directly mutate mastery. Never store raw keystrokes as telemetry. Never expose generated content before executable validation. Never combine independent and AI-collaboration scores into one opaque total.\n\n---\n\n### Task 1: Mentor quality benchmark v2\n\n**Files:** `quality/mentor-diagnosis-v2.json`, `scripts/lib/mentor-benchmark-v2.mjs`, `scripts/lib/mentor-benchmark-v2.test.mjs`, `scripts/check-mentor-quality-v2.mjs`, `package.json`, `docs/quality/mentor-diagnosis-v2-report.json`\n\n1. Write failing tests for provenance validation and all six required metrics.\n2. Implement case validation, segmented metrics, real-case counts, and hard gate status.\n3. Seed migration-compatible cases without presenting synthetic cases as real.\n4. Add deterministic report generation and package command.\n\n### Task 2: Evidence envelope and review workbench\n\n**Files:** gateway quality domain/routes/tests, `web/src/lib/quality-review.ts`, tests, `web/src/pages/QualityWorkbenchPage.tsx`, route/navigation files, styles.\n\n1. Write failing tests for immutable attempt binding, blind ordering, human authority, model calibration, and disagreement queues.\n2. Implement an auditable review store and API contracts.\n3. Build the internal comparison workbench and regression status UI.\n4. Verify that every verdict links to the evidence envelope.\n\n### Task 3: Pedagogical events and deterministic learner projection\n\n**Files:** `web/src/lib/pedagogical-events.ts`, `web/src/lib/learning-projection.ts`, matching tests, gateway validation/store tests, learner timeline UI.\n\n1. Write failing tests for bounded semantic events and rejection of raw noise.\n2. Implement five-stage phase replay.\n3. Implement pure mastery contributions and an auditable contribution ledger.\n4. Render evidence-driven state changes and critical-node replay.\n\n### Task 4: Adaptive beginner curriculum\n\n**Files:** curriculum/lesson-progress modules and tests, interactive visualization component, lesson page/map, styles.\n\n1. Write failing graph validation and five-stage readiness tests.\n2. Extend lesson nodes with prerequisites, prediction, visualization, partial coding, full practice, transfer, and delayed review.\n3. Implement minimum-remediation routing and return-to-problem state.\n4. Add hidden transfer and delayed-review scheduling/projection.\n\n### Task 5: Dual-mode algorithm screening\n\n**Files:** exam modules/tests, exam workspace/page/report UI, persistence migration, styles.\n\n1. Write failing migration and mode-policy tests.\n2. Preserve independent mode behavior and add explicit no-AI policy.\n3. Add structured AI-collaboration events and oral follow-up evidence.\n4. Produce four independent report dimensions with evidence references.\n\n### Task 6: Trusted generated content\n\n**Files:** `web/src/lib/content-trust.ts`, tests, gateway generation validation adapter/tests, review workbench integration.\n\n1. Write failing trust-transition and execution-validation tests.\n2. Implement candidate, auto-validated, and human-verified states.\n3. Validate generated analogy, counterexample, and transfer content through executable checks.\n4. Add expansion gates that remain closed without quality/effectiveness evidence.\n\n### Task 7: Real public submission ingestion\n\n**Files:** `scripts/import-mentor-cases.mjs`, tests, provenance manifest/schema, documentation.\n\n1. Write failing tests for local Project CodeNet-style metadata/source ingestion, deduplication, and pending-adjudication state.\n2. Implement a local/offline importer with source URL, license/provenance manifest, language, verdict, and code hash.\n3. Import a manageable official public sample if available; otherwise leave the release gate truthfully red and document the exact ingestion command.\n4. Never infer teacher gold labels from verdict alone.\n\n### Task 8: Integration, browser verification, and milestone audit\n\n**Files:** README, OpenSpec tasks, quality docs, affected route/style files.\n\n1. Run focused and full tests, lint, typecheck, build, gateway tests, and quality gates.\n2. Start the app and gateway; smoke-test Today, lesson, problem mentor, exam modes, and quality workbench.\n3. Perform ship-readiness and independent code review.\n4. Record Done/Partial/Blocked for every OpenSpec task, including the eligible real-adjudicated case count.\n\n
