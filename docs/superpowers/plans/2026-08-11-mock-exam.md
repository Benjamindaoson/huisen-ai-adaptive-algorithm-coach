# OD 模拟考试实施计划

> 日期：2026-08-11
> 范围：浏览器本地第一版，公开样例评分；为后续服务端隐藏用例判题预留契约。

## 目标

把当前题库中的“单题练习”扩展为一个可信、可恢复、不会泄露题解的模拟考试流程：用户从首页开始考试，在固定截止时间内完成多道题，刷新后继续，提交后得到逐题报告、技能薄弱点和下一步建议。

## 验收标准

1. 首页可开始一场 3 题模拟考试，题目只从内容完整且支持代码语言的条目中选择。
2. 考试使用绝对截止时间；刷新页面不会重置或延长时间。
3. 每道题的语言与代码自动保存到浏览器，切题及刷新后可恢复。
4. 考试进行中不显示题解、参考答案、AI 教练或历史答案。
5. 用户可运行自定义输入调试，但“提交考试”才会批量运行公开样例并生成报告。
6. 报告明确标注为“公开样例模拟分”，不伪装成隐藏用例 AC。
7. 报告展示总分、耗时、逐题结果、失败原因和技能建议。
8. 自动到时与手动提交使用同一条提交链路，并防止重复提交。
9. 单元测试、类型检查、lint、构建和本地浏览器主流程全部通过。

## 数据模型

新增 `web/src/lib/exam.ts`：

- `ExamSession`：考试 ID、状态、题目 ID、当前题目、开始/截止时间、答案、报告。
- `ExamAnswer`：题目 ID、语言、代码、更新时间。
- `ExamProblemResult`：逐题 verdict、公开样例通过数、错误摘要、耗时。
- `ExamReport`：提交时间、总耗时、模拟分、逐题结果。
- 严格的本地存储解析与版本字段，损坏数据安全降级为无考试。

核心约束：剩余时间始终由 `deadlineAt - Date.now()` 计算，绝不持久化“剩余秒数”。

## 页面与交互

### 首页入口

- 新增“OD 模拟考试”卡片。
- 显示考试规格：3 题、固定时长、公开样例评分。
- 有未结束考试时显示“继续考试”，已提交时显示“查看报告/重新开始”。

### 考试工作台 `#/exam`

- 顶部：考试状态、倒计时、提交按钮。
- 左侧：题目描述与题号导航，只显示题面。
- 右侧：语言选择、代码编辑器、自定义输入与运行结果。
- 不复用会暴露题解和 AI 教练的普通 `ProblemReader`。

### 考试报告

- 总分采用通过公开样例的题目占比，标注“公开样例模拟分”。
- 逐题展示：通过、未通过、未作答、不可判定、运行错误。
- 根据失败题目的技能标签生成复习建议与返回练习入口。

## 执行步骤

### 1. 本地考试领域层（TDD）

- 先写失败测试：绝对截止时间、答案隔离、持久化恢复、非法数据拒绝、提交幂等。
- 实现 `exam.ts` 的纯函数与存储适配器。

### 2. 选题策略（TDD）

- 先写失败测试：只选择完整、可运行题目；尽量覆盖不同技能；固定输入得到稳定结果。
- 实现轻量的确定性选题，不引入随机不可复现行为。

### 3. 考试 UI（TDD）

- 先写组件测试：考试中无“题解/AI 教练/参考答案”；答案切换可恢复；报告明确样例评分。
- 实现 `ExamWorkspace`、首页入口和 `#/exam` 路由。

### 4. 批量提交与报告（TDD）

- 复用现有 Judge0 客户端和样例判题层，逐题执行公开样例。
- 防止重复提交；捕获超时、编译错误、无结构化样例等情况。
- 自动到时触发同一提交函数。

### 5. 质量验证

- 运行单测、lint、类型检查、构建和 OpenSpec 校验。
- 启动本地服务，在真实浏览器验证开始考试、切题、运行、刷新恢复、提交、报告和响应式布局。

## 后续隐藏用例判题边界

第一版本不把公开样例结果称为 AC。后续服务端阶段新增：

- `POST /submissions`：只接收题目 ID、语言和源码。
- `GET /submissions/:id`：轮询状态和汇总结果，不返回隐藏输入或期望输出。
- 服务端私有测试包、资源限制、沙箱执行和用例版本号。
- 报告同时保留 `sampleScore` 与 `hiddenVerdict`，避免概念混淆。

在私有测试包尚未建立前，OpenSpec 的“隐藏用例提交”任务保持未完成状态。
