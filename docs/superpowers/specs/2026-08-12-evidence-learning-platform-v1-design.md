# Evidence Learning Platform v1 Design\n\n## Product outcome\n\nThe product must stop presenting an ordinary problem bank with an AI chat tab. It becomes an evidence-driven learning system whose promise is: **not to solve this problem for the learner, but to make the learner independently solve the next one**.\n\nThe implementation is governed by `openspec/changes/build-evidence-learning-platform-v1/`. The OpenSpec proposal, design, and five capability specifications are the normative product contracts.\n\n## Non-negotiable design rules\n\n1. A mentor conclusion is never freestanding. It is bound to an immutable attempt, executed run, tool evidence, and current-code diff.\n2. Synthetic submissions can exercise software but cannot be presented as real learner evidence.\n3. Human adjudication is authoritative. A model judge is a calibrated assistant whose disagreement is visible.\n4. Telemetry records meaningful teaching events, not keystroke exhaust or raw source-code surveillance.\n5. Learner-state changes are deterministic projections from explainable events; a model cannot directly assign mastery.\n6. Learning nodes combine explanation, prediction, visualization, partial coding, and complete practice.\n7. Independent and AI-collaboration exams report different abilities and never collapse into an opaque total.\n8. Generated learning content has explicit provenance and trust states and must execute successfully before learner exposure.\n\n## Evidence architecture\n\nEvery diagnosis uses an `EvidenceEnvelope` containing attempt identity, source snapshot hash, run results, tool calls, conclusions, evidence references, current-code hash, and a bounded diff. The envelope is the join key for quality evaluation, the mentor timeline, human review, and learner replay.\n\nQuality cases declare origin (`first-party-observed`, `public-dataset`, or `synthetic-mutation`) and adjudication state. Only teacher-adjudicated first-party observations or eligible public-dataset cases count toward the real-case release gate.\n\n## Quality governance\n\nThe benchmark reports localization, misconception classification, evidence sufficiency, minimal-hint effectiveness, answer leakage, and false conclusions. Metrics are sliced by language, error family, and learner level. Release status must remain red if the eligible real adjudicated set is below 100, even when synthetic regression tests pass.\n\nThe internal workbench provides blind randomized A/B comparison, teacher verdicts, model-judge verdicts, calibration summaries, disagreement queues, and regression gate state. It never allows a model verdict to silently override a teacher.\n\n## Learning architecture\n\nSemantic events map work into understanding, modeling, implementation, debugging, and validation phases. A pure projector derives the learner twin and records each contribution so the learner or reviewer can see which evidence changed which estimate.\n\nThe curriculum is a prerequisite graph. A lesson is considered complete only after its five-stage learn-practice sequence, a hidden transfer attempt, and delayed review evidence where required. Misconceptions route to the smallest prerequisite node and then return to the interrupted problem.\n\n## Assessment architecture\n\nIndependent mode disables mentor assistance and measures algorithm execution under exam constraints. AI-collaboration mode captures planning, delegation, evidence review, test construction, corrections, and oral explanation. Reports expose algorithm ability, independent completion, hint dependence, and AI collaboration separately.\n\n## Honest milestone boundary\n\nThe repository does not currently contain 100 teacher-adjudicated first-party learner submissions. This version therefore implements the real-data schema, importer, review flow, metrics, and hard gate, but it must not claim the real-case milestone until the imported cases have valid provenance and completed adjudication.\n\n
