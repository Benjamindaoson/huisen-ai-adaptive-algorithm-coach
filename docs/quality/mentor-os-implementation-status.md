# Mentor OS 实现与证据状态

更新日期：2026-08-12

## 已实现的软件能力

- 一个持久、幂等、带序列检查点的 Mentor Run；支持启动、上下文贡献、行动、审批、停止、恢复和 SSE 事件游标。
- Today、Learn、Practice、Review、AI 协作考试、Insights 的受限上下文贡献；禁止原始键击、隐藏测试、隐藏输出和任意完整会话噪声进入编译器。
- 新 Mentor OS 命令真实包装现有动态 Mentor 引擎。运行会记录 DeepSeek/确定性模式、AST/语义分析、可信检索、反例/验证工具、假设、证据缺口、验证与显式停止原因。
- 全局持续导师 Dock。它明确区分“只同步上下文”“Agent 已执行工具”“服务不可用”，并持续显示一个下一步。
- 代码修改先请求审批；学习者接受或拒绝形成不可变事件。在没有批准记录时不会自动应用修改。
- 独立考试、独立迁移和延迟复测在策略层禁用模型、工具、提示、参考答案与编辑；AI 协作考试单独保留可审计协作证据。
- v5 本地备份覆盖 Mentor OS 检查点、审批、实验和结果关联；兼容 v1–v4 迁移。

## 本轮验证证据

- `npm test`：115 个测试文件、430 个测试通过。
- `npm run lint`：通过，无 warning。
- `npm run typecheck`：Web 与 Gateway 通过。
- `npm run build:web`：Vite 生产构建通过。
- `npx openspec validate build-ai-native-mentor-os --strict`：通过。
- `npm run quality:golden`：100/100 注释合同通过；只有 4 道题的公开内容经过人工复核，技能分类仍未人工 verified。
- `npm run quality:mentor:seed`：12 个合成种子夹具的错因与行定位为 100%，仅是回归基线。
- 真实浏览器：Today → 学习中心 → 题目工作台跨路由保留同一 Mentor Run；本地 DeepSeek `deepseek-v4-flash` 实际调用 2 次模型并执行 3 个工具（Java AST/语义结构、4063 文档可信索引检索、苏格拉底提问）；全局 Dock 从共享游标恢复了工具事件和停止原因；浏览器 console 无当前运行错误。

## 仍然没有被验证的事情

- `npm run quality:mentor` 当前按设计失败：4 个种子案例有预测，教师裁决的真实合格错误提交仍为 **0/100**。因此不能声称诊断质量已经优于通用模型。
- 没有真实纵向 cohort 证明 Mentor 提高了下一道同技能题、不同表面迁移题或延迟复测的独立通过率。
- 本地烟测时 Judge0 执行服务不可用；Mentor 对该事实标记为 `unavailable`，仍能执行静态结构与可信检索，但没有伪造运行时证据。
- SSE 当前承担生命周期投影与游标恢复；生产级长连接容量、跨实例广播、PostgreSQL 事件适配和组织级权限仍需要部署环境验证。
- 这是一套可运行的 Agent 系统与 AI 原生交互骨架，不等于已经达到“100% 经过真实教学效果验证”。发布门禁会继续保持关闭，直到真实教师裁决和纵向学习数据满足阈值。
