# Mentor 诊断质量基线

## 这套基线解决什么

Mentor 不再只以“模型能返回一段话”作为完成标准。`quality/mentor-diagnosis-v1.json` 用独立、人工编写的观察标签描述每个案例应当定位的代码行、误区类型、最小提示意图，以及绝不能直接泄露的答案片段。`npm run quality:mentor` 会验证数据边界并生成机器可读报告。

当前指标包括：

- 错误行定位准确率；
- 误区分类准确率；
- 高置信但无证据结论率；
- 最小提示意图有效率；
- 答案泄露率。

目标阈值分别是 `80%`、`70%`、`≤2%`、`40%` 和 `0%`。

## 当前真实成熟度

当前只有 12 条种子案例，覆盖 JavaScript、Python、Java、C++ 和边界、输入、状态、复杂度、输出格式等常见错误。报告中的 100% 代表“评测器可以正确评分这组人工复核示例输出”，不代表 DeepSeek 已在真实学习者提交上达到 100%。报告会将成熟度标记为 `seed-baseline`，并保留这一限制说明。

在达到以下规模前，本报告不能作为模型上线质量证明：

- 至少 100 条与实现者隔离标注的金标失败提交；
- 至少 20% 的双人交叉标注与分歧仲裁；
- 覆盖四种语言、主要错误类型、无错代码和证据不足案例；
- 使用真实 Mentor 输出，而不是人工示例预测；
- 单独统计不同难度、语言和证据等级，避免平均数掩盖弱项。

## 使用方法

```powershell
npm run quality:mentor
```

报告生成到 `docs/quality/mentor-diagnosis-report.json`。未来的实时 DeepSeek 实验只需输出相同的 prediction schema，就能和确定性基线使用同一套评测器；模型密钥仍只放在服务端环境变量中。
