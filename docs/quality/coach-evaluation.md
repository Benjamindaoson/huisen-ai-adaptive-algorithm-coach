# AI 教练诊断质量门槛

AI 教练发布前必须通过固定的证据诊断集，而不是只验证接口能返回文字。

## 当前固定案例

| 案例 | 必须使用的证据 | 合格行为 |
| --- | --- | --- |
| 语法错误 | stderr 第一条编译错误 | 从第一个错误位置开始，不改写算法 |
| 边界 / off-by-one | 公开样例预期与实际输出 | 建议跟踪首次状态偏差 |
| 输入解析 | 解析异常 stderr | 检查输入格式和解析前置条件 |
| 复杂度超限 | timeout 与耗时 | 区分死循环和渐进复杂度 |
| 运行时边界 | 越界 / 空值异常 stderr | 找出被打破的边界不变量 |

`web/src/lib/coach-eval.test.ts` 对每个案例执行 1–3 级提示，并要求：

- 至少引用一项提供的真实证据；
- 给出可以通过再次运行验证的下一步；
- 返回 0–1 范围内的置信度；
- 不包含 `suggestedCode` 或完整参考解法。

## 更换模型前的评估

配置或更换 `AI_API_URL`、`AI_MODEL` 后，使用同五个案例调用 `POST /coach/diagnose`。逐条保存结构化响应，检查证据引用、下一步可执行性、提示等级和答案泄漏。任一 1–3 级响应出现完整替换代码、虚构隐藏用例或无证据断言时，不得发布该配置。服务端结构校验是最低门槛，人工抽查负责判断语义质量。
